# Python 学习计划（每周 2 课，必修 29 课 + 选做 6 课）

## 这个计划到底在教什么

不是"教你写 Python"。

你已经做出过 calendar-app —— React + Express + SQLite + JWT + AI 解析，部署在自己的服务器上。
那个项目证明了一件事：**你指挥 AI 做项目的能力，已经比大多数成年人强。**

但那个能力有个天花板：**你没法判断 AI 给你的东西对不对。**
AI 写了一段 `except:` 把所有错误吞掉，你看不出来；它编了一个不存在的函数名，你也看不出来。
项目能跑，你就以为对了。跑不了，你只能再问一次 AI。

所以这个计划的真正目标是三件事：

| 目标 | 说人话 |
|---|---|
| **1. 会用 AI 学** | 问"给我解释"而不是"给我代码"。会追问，会发现 AI 在瞎编 |
| **2. 会审 AI 的代码** | 读得懂它写的东西，能指出问题，知道哪些活不该交给它 |
| **3. 会把 AI 当零件** | 用 Python 调 API，让 AI 变成你程序里的一个函数 |

**手写代码是手段，不是目的。** 你手写，是为了拿到"审判 AI 输出"的资格。
这就是为什么练习题我不代写 —— 不是要为难你，是代写了这个计划就没意义了。

## 节奏：每周 2 课

不排日期了。原来按天排，你落后了两周，日期除了让你有负罪感没别的作用。

**每节课约 2 小时**，安排在一周里的任意两天。中间隔几天是好事 —— 隔一段时间再回来，
才知道哪些是真记住了，哪些是当时抄下来的。

| 时段 | 做什么 |
|---|---|
| 前 10 分钟 | 打开上一课写的文件，重读自己的代码。看不懂了就说明当时没学懂，先补 |
| 中间 40 分钟 | 看这节课文件里的「先讲人话」和「读一读」，**边看边跟着敲**，不要只看 |
| 后 50 分钟 | 做「练一练」。卡住先自己想 10 分钟 |
| 再 10 分钟 | 做「问 AI」那一段 —— 这段别跳过，它是这个计划的核心 |
| 最后 10 分钟 | 写 `lessonNN_summary.md`（格式见 `SUMMARY_TEMPLATE.md`），然后 git commit |

**三条规则（比计划本身更重要）**

1. **练习必须自己手写。** 可以问我原理、让我看报错、让我 review 写完的代码，但不要让我代写。
2. **卡住超过 20 分钟就来问我。** 不要死磕，也不要跳过。问的时候把你的代码和报错一起发我。
3. **宁可少写不要不写。** 只有 30 分钟就做第 1 题。断一课比断一个月好补。

**主教程**：廖雪峰 Python 教程 https://liaoxuefeng.com/books/python/
**查语法**：菜鸟教程 https://www.runoob.com/python3/python3-tutorial.html

## 环境

Python 3.14.5 + VS Code 都装好了。需要的三件事：

1. VS Code 扩展：`Python`（发布者 Microsoft）、`Ruff`（发布者 Astral Software）
2. `File → Open Folder` → 选你本地 `Study` 仓库里的 `python` 文件夹
3. 快捷键：`Ctrl + 反引号` 开终端，`Cmd + S` 保存

**关于虚拟环境（venv）**：暂时不用。它解决的是"两个项目要不同版本的同一个库"的冲突，
你现在只有一个项目，没有冲突可解，而每开一个终端都要 `activate` 的成本是实打实的
（第 13 课你已经踩过一次这个坑）。装包直接 `pip3 install`，跑代码直接 `python3`。

但 `requirements.txt` 要写 —— 记录这个项目用到哪些库，这个习惯跟 venv 无关。
真正需要 venv 的那天（你同时搞两个项目、版本打架），你会立刻明白它在解决什么，那时候再学。

## 学完你应该能做到

- 不查资料写出 100 行左右的 Python 程序

- 给自己的函数写自测，证明它是对的，而不是"看起来能跑"
- **读 AI 写的代码时，能指出它哪里偷懒了**
- **知道一个任务该不该交给 AI，以及怎么问才问得好**

## 卡住了怎么办

按这个顺序：

1. **读报错最后一行**。Python 报错信息很友好，最后一行就是原因。
2. **`print` 大法**。不知道哪错了就到处 `print(变量)`，看值对不对。
3. **查菜鸟教程 / 官方文档**。语法忘了就查，这不算作弊，专业程序员天天查。
4. **问 AI —— 但要问对**。别说"帮我改"，说"这段报了这个错，我以为它会 XX，
   为什么不是？"前者你得到一段代码，后者你得到一个解释。
5. **来问我**。带上：你想做什么、你写的代码、完整报错。别只说"我的代码跑不了"。
