# 第 16 课学习总结

## 为什么学这个很重要

| 重要点 | 说明 |
| --- | --- |
| 时间是程序里最容易出错的东西之一 | 日期和时间看起来简单，但跨月、跨年、闰年时，自己算就很容易错。 |
| 字符串和日期对象不是一回事 | "2026-08-29" 是字符串，不能直接拿来算；`date(2026, 8, 29)` 才是可以比较、相减的对象。 |
| `date` / `datetime` 能帮你做正确计算 | 相减、加减、比较都比手写公式更稳，尤其是 30 天、闰年这些边界情况。 |
| 不能直接拿字符串比大小 | 字符串比大小只看字符，不看日期的真实含义，所以很容易出错。 |
| `try/except` 是处理不确定输入的关键 | 用户输入格式可能不统一，程序需要“试着解析，失败就处理一下”。 |
| 这节课是“真实项目里会常用的基础” | 复习提醒、日程安排、时间筛选，这些都离不开日期计算。 |
| AI 也会算错日期 | AI 不知道今天几号，不能当作时间计算器；日期要自己算好，再喂给 AI。 |

## 学习目标与真正学会的内容

| 学习目标 | 真正学会的内容（含例子） |
| --- | --- |
| 会区分 `date` 和 `datetime`。 | `date` 只保留年月日；`datetime` 还带时间。 |
| 会用 `date.today()`。 | `today = date.today()` 可以拿到今天的日期。 |
| 会用 `date.fromisoformat()`。 | `date.fromisoformat("2026-08-29")` 能把字符串变成日期对象。 |
| 会用 `strftime()`。 | `dt.strftime("%Y-%m-%d")` 可以把对象变成字符串。 |
| 会用 `strptime()`。 | `datetime.strptime("2026-08-29 15:30", "%Y-%m-%d %H:%M")` 能把字符串解析成时间。 |
| 会理解 `timedelta`。 | `timedelta(days=1)`、`timedelta(hours=2)` 都是“长度”，不是某个特定时刻。 |
| 会做日期相减。 | `(date(2026, 9, 3) - date(2026, 8, 28)).days` 能得到真实天数差。 |
| 会写 `friendly()`。 | 把日期转换成 “今天 / 昨天 / 3 天前 / 1 周前 / 还没到” 这种人话表达。 |
| 会写 `days_since()`。 | 把字符串日期转成 `date`，再减今天，得出相差多少天。 |
| 会用 `try/except` 处理解析失败。 | 当字符串不是合法日期时，程序不再直接崩掉，而是进入 `except`。 |
| 会理解“最该复习”这类逻辑。 | 不是“看起来像要复习”，而是“今天 >= 该复习日期” 才算到期。 |

## 练习里你能直接回顾的点

| 复习点 |
| --- |
| `date.fromisoformat()` 是“字符串转对象”。 |
| `strftime()` 是“对象转字符串”。 |
| `datetime.strptime()` 要和格式串完全一致。 |
| `timedelta` 只能做固定长度的加减，不支持 `months`。 |
| 日期比较不能直接拿字符串比，容易出错。 |
| `date1 - date2` 得到的是 `timedelta`，想拿天数要用 `.days`。 |
| `try/except ValueError` 很适合处理日期解析失败。 |
| `today_ >= next_due` 表示今天该复习。 |
| `next_due` 最早的那一节，通常就是最该复习的那一节。 |
| 复习题的关键不是“写出代码”，而是“把规则翻成代码”。 |

## 今天实践的代码

### 1. `days_since()`
```python
def days_since(iso_str):
    target_day = date.fromisoformat(iso_str)
    return (date.today() - target_day).days
```

这个函数的核心是：
- 先把字符串转换成 `date`
- 再做减法
- 最后拿 `.days`，得到天数差

### 2. `friendly()`
```python
def friendly(iso_str):
    target = date.fromisoformat(iso_str)
    today = date.today()
    delta = (today - target).days

    if delta < 0:
        return "还没到"
    if delta == 0:
        return "今天"
    if delta == 1:
        return "昨天"
    if 2 <= delta <= 6:
        return f"{delta} 天前"
    if 7 <= delta <= 29:
        return f"{delta // 7} 周前"
    return iso_str
```

这个函数很像“人类说时间”的方式：
- 0 天 → 今天
- 1 天 → 昨天
- 2 到 6 天 → 几天前
- 7 到 29 天 → 几周前
- 太久了就直接显示原日期

### 3. 字符串比较 vs 日期比较
```python
def demo_reverse_compare():
    s1 = "2026-9-15"
    s2 = "2026-10-01"

    try:
        d1 = datetime.strptime(s1, "%Y-%m-%d").date()
        d2 = datetime.strptime(s2, "%Y-%m-%d").date()

        print("字符串比较：", s1 < s2)
        print("真实日期比较：", d1 < d2)

    except ValueError:
        print("日期格式不对，不能转换成 date 对象")
```

这段代码说明了一件很重要的事：
- 字符串比较会按字符逐位比较
- 真实日期比较才是按时间顺序比较

### 4. `parse_flexible()`
```python
def parse_flexible(text):
    try:
        return date.fromisoformat(text)
    except ValueError:
        pass

    try:
        return date.fromisoformat(text.replace("/", "-"))
    except ValueError:
        pass

    return None
```

这个函数的思路很实用：
- 先试一种格式
- 试不出来就继续下一种
- 真的不行了，返回 `None`

## 这一天最重要的提醒

- 只要涉及“日期比较”“时间计算”“跨月跨年”，就不要直接拿字符串比。 |
- `date` / `datetime` 是中间层，字符串只是两头。 |
- `timedelta` 适合固定长度，不适合“一个月”这种模糊概念。 |
- `try/except` 不是“为了写而写”，而是让程序更稳。 |
- 一句需求写不清楚，AI 给出的代码也常常不对。 |
- 正确的思维不是“我会写”，而是“我知道为什么这么写”。 |

## 我的真实体会

这节课最难的地方不是数学，而是思想转换。以前我会觉得“日期就只是字符串”，但后面一旦遇到 9 月和 10 月、闰年、跨月一类情况，就马上发现字符串根本不能当真时间。真正让我进步的是，我开始理解：程序里最重要的不是“看起来像日期”，而是“你能不能把它变成真正可计算的对象”。

`friendly()` 这类函数也让我明白，程序和人对时间的表达不同。用户想要的是自然语言，程序想要的是准确计算。最好的代码通常是两者中间的桥梁。最后一题“最该复习的那一节”让我感觉到，编程不是会背语法，而是会把一句话翻成条件判断。这是以后写工具最关键的能力。

## 一句话总结

第 16 课的核心是：日期不能直接拿字符串比较，要先转成 `date` / `datetime`，再做加减、比较和判断；而 `try/except` 则是处理不确定输入格式时最基本、最实用的保护机制。
